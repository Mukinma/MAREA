# Recorridos 360° y AR — implementación

Objetivo autorizado: captura esférica 360° × 180° en celular, procesamiento Cloud Run Jobs/Hugin/Enblend, versiones privadas/publicadas en Supabase, visita virtual, AR por imagen y descubrimiento cercano. Especificación de producto: docs/ar-experience-design.md, actualizada a 360° durante esta implementación.

## Entregables

1. Backend y procesamiento: migraciones aditivas, RLS, cola/leases/cupos, Hugin, importación, dispatcher Google autenticado, infraestructura reproducible, eliminación de cuenta y pruebas.
2. Aplicación: modelos/repositorios, captura orientada persistente y TUS, asistente editorial, visor y navegación, solicitudes/revisión, descubrimiento y progreso.
3. Integraciones nativas: orientación/campo de visión, ARCore/ARKit con referencias de ancho conocido, lifecycle y fallback.
4. Documentación e ImageGen: referencias actualizadas y verificación Flutter/SQL/worker/builds. Validación física y despliegue requieren dispositivos, fotografías y credenciales reales disponibles.

## Contrato compartido

Los RPC devuelven JSON. Tour: `id, owner_id, title, state, revision_id, public_revision_id, space, document`. Space: `id, name, location_label, latitude, longitude, verified, context, evidence_paths`. Document: `start_scene_id, zones, ar_order, starts_at, ends_at`. Zone: `id,name,description,scenes`. Scene: `id,name,job_id,panorama_path,preview_path,thumbnail_path,initial_yaw,connections,points`. Connection: `id,target_scene_id,yaw,pitch,label,instruction`. Point: `id,name,description,yaw,pitch,link,ar`. Link: `kind,id,owner_id,title,status` (`showcase/post/mission`; lookup resuelve existencia/permisos/título reales). AR: `reference_path,width_cm,reference_version,tested_version`. Ángulos en grados: yaw [-180,180), pitch [-90,90]. Identificadores UUID. Paths de medios relativos al bucket, nunca URLs arbitrarias.

RPC autenticados: `tours_list(p_owner uuid default null,p_lat double precision default null,p_lng double precision default null)` → Tour[]; `tours_public_list(p_owner uuid)` → versiones públicas activas (también para el autor que edita un borrador); `tours_get(p_tour uuid,p_edit boolean default false)` → Tour/null; `tours_save(p_tour uuid,p_title text,p_space jsonb,p_document jsonb)` → Tour; `tours_submit(p_tour uuid)` → Tour; `tours_pause(p_tour uuid,p_paused boolean)`; `tours_requests()` → solicitudes; `tours_review(p_request uuid,p_approve boolean,p_reason text)`; `tours_permission_revoke(p_request uuid)`; `tours_link_search(p_query text)` → Link[]; `tours_link_request(p_tour uuid,p_point uuid)`; `tours_progress(p_tour uuid,p_revision uuid,p_progress jsonb default null)` → progreso/null; `tours_capture_begin(p_tour uuid,p_scene uuid,p_mode text)` → {id}; `tours_capture_submit(p_capture uuid,p_manifest jsonb)` → Job; `tours_job_get(p_job uuid)` → Job; `tours_job_cancel(p_job uuid)`; `tours_attach_result(p_tour uuid,p_scene uuid,p_job uuid)` → Tour; `tours_ar_report_test(p_tour uuid,p_point uuid,p_reference_version uuid,p_platform text,p_tracking_seconds integer)` → reporte ligado a referencia vigente. Publicar/revisar aplica permisos y congela versión en servidor. Reanudar exige conservar el permiso espacial vigente.

Solo backend: claim/context/current/finish, guardas de escritura/GC y `tours_completion_receipt(p_job uuid,p_lease uuid)`. Un finish repetido con el mismo lease/resultado comprometido es idempotente; una respuesta ambigua conserva medios hasta reconciliar el recibo. Credenciales de servicio no entran al cliente.

Job: `id,capture_id,state,error_code,message,result,attempts`. Result: `panorama_path,preview_path,thumbnail_path`. Manifest: `{frames:[{id,path,width,height,yaw,pitch,roll,hfov,vfov,target_id}], mode:'photos'|'import'}`. Captura queda inmutable al enviar. Importación requiere GPano de esfera completa o rechazo con explicación; un JPEG 2:1 normal no acredita proyección. Worker verifica archivos y cobertura real. Bucket `tour-inputs`: owner/capture/frame.jpg. Bucket `tour-assets`: owner/jobs/job/{panorama,preview,thumbnail}.jpg y owner/references/UUID.jpg. Responsables/clientes no pueden fabricar resultados/progreso de jobs.

Servicios nativos Flutter: MethodChannel `marea/tour_motion` métodos `start`, `stop`, `cameraInfo`; EventChannel `marea/tour_motion/events` con `yaw,pitch,roll` en grados y timestamp; yaw relativo al inicio y pitch respecto a gravedad. Captura fija en portraitUp. `cameraInfo({cameraName,imageWidth,imageHeight})` usa dimensiones del JPEG de calibración EXIF aplicado y devuelve `hfov,vfov`. Retomar comprueba cámara/FOV y exige realinear la primera toma. MethodChannel `marea/tour_ar` método `supported`; PlatformView `marea/tour_ar_view` creationParams `{references:[{id,path,widthMeters}]}` con paths locales. EventChannel `marea/tour_ar/events` emite `{id,state:'tracking'|'lost'|'error',message?}`. Android/iOS descargan referencias privadas antes de iniciar; nunca simular reconocimiento.

## Límites y verificación

Cloud Run: proyecto marea-f6a92, us-central1, CPU 4, RAM 8 GiB, timeout 900s, dos cupos globales en DB; tres intentos totales solo errores transitorios. Salidas 4096×2048, 2048×1024 y miniatura. Verificación: tests unitarios/widget, contratos PGlite, worker, compilaciones Android/iOS/web y revisión independiente. No integrar ni publicar cambios ajenos.
